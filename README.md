# 🎬 CineBook — DBMS Mini Project

A small Spring Boot web application that manages a `MOVIE` table in a **persistent, file-based H2 database** using **plain JDBC**.

It supports **exactly three operations**:

| # | Operation              | HTTP endpoint                | SQL executed (parameterized)                                              |
|---|------------------------|------------------------------|---------------------------------------------------------------------------|
| 1 | **Insert** a movie     | `POST   /api/movies`         | `INSERT INTO MOVIE (title, genre, ticket_price) VALUES (?, ?, ?)`         |
| 2 | **Update** a movie by ID | `PUT    /api/movies/{id}`  | `UPDATE MOVIE SET title = ?, genre = ?, ticket_price = ? WHERE movie_id = ?` |
| 3 | **Delete** a movie by ID | `DELETE /api/movies/{id}`  | `DELETE FROM MOVIE WHERE movie_id = ?`                                    |

Listing, searching, login and ticket booking are intentionally **not** implemented.

---

## Tech stack

- Java 17 (compiled with `--release 17`; also runs on newer JDKs such as 21)
- Spring Boot 3.3.5 (Web, JDBC, Validation)
- Maven (with Maven Wrapper — no local Maven install needed)
- H2 Database in file mode (`./data/cinebook.mv.db`)
- Frontend: HTML, CSS, vanilla JavaScript (no frameworks)

## Prerequisites

- **JDK 17 or newer** on your `PATH` (`java -version` must report 17+).
- Internet access on the first build (the wrapper downloads Maven 3.9.9 and the dependencies).

## How to run

From the project root:

**Linux / macOS**
```bash
./mvnw spring-boot:run
```

**Windows (Command Prompt / PowerShell)**
```bat
mvnw.cmd spring-boot:run
```

Then open **http://localhost:8080** in your browser.

Stop the app with `Ctrl + C`.

### Run as a JAR (alternative)

```bash
./mvnw clean package          # Windows: mvnw.cmd clean package
java -jar target/cinebook-1.0.0.jar
```

### Change the port

```bash
PORT=9090 ./mvnw spring-boot:run            # Linux / macOS
set PORT=9090 && mvnw.cmd spring-boot:run   # Windows cmd
```

## How to run the tests

```bash
./mvnw test                   # Windows: mvnw.cmd test
```

The test suite (14 tests) covers:

- insert / update / delete success paths, verified directly against the database;
- validation failures (blank fields, too-long text, illegal characters, zero/negative/too-large prices, more than 2 decimals, malformed JSON, invalid IDs);
- `404 Not Found` for update/delete of a non-existent ID;
- an SQL-injection string being stored as plain text (proving parameterized SQL);
- that list/fetch endpoints are **not** exposed;
- persistence: the app is started twice against the same H2 **file** database and data written in the first run is read back in the second.

Tests use an in-memory H2 database (`src/test/resources/application.properties`), so they never touch your real `./data` file. The persistence test uses its own temporary file database.

## Database

### Schema (`src/main/resources/schema.sql`)

```sql
CREATE TABLE IF NOT EXISTS MOVIE (
    movie_id     BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    title        VARCHAR(100)  NOT NULL,
    genre        VARCHAR(50)   NOT NULL,
    ticket_price DECIMAL(7, 2) NOT NULL,
    CONSTRAINT chk_movie_title_not_blank CHECK (LENGTH(TRIM(title)) > 0),
    CONSTRAINT chk_movie_genre_not_blank CHECK (LENGTH(TRIM(genre)) > 0),
    CONSTRAINT chk_movie_ticket_price    CHECK (ticket_price > 0 AND ticket_price <= 10000)
);
```

The script runs on every startup (`spring.sql.init.mode=always`). Because it uses `CREATE TABLE IF NOT EXISTS`, existing data is preserved between restarts.

### Persistence

`src/main/resources/application.properties`:

```properties
spring.datasource.url=jdbc:h2:file:./data/cinebook;DB_CLOSE_ON_EXIT=FALSE
```

The data file is created at `./data/cinebook.mv.db`, relative to the directory you start the app from. Always start it from the project root so the same file is used. To reset the database, stop the app and delete the `data/` folder.

`movie_id` is generated by the database. The ID of a newly added movie is shown in the success message on the **Add Movie** form. Use that ID with **Update Movie** and **Delete Movie**.

## Validation rules

Validation is done in the browser (for quick feedback), on the server with Bean Validation (authoritative), and by the database `CHECK` constraints.

| Field          | Rule                                                                                         |
|----------------|----------------------------------------------------------------------------------------------|
| `movie_id`     | Positive whole number (path parameter for update/delete)                                     |
| `title`        | Required, 1–100 chars after trimming; starts with a letter/digit; letters, digits, spaces and `. , : ; ! ? ' & ( ) -` |
| `genre`        | Required, 1–50 chars after trimming; starts with a letter; letters, spaces and `& / -`       |
| `ticket_price` | Required number, `0.01`–`10000.00`, at most 2 decimal places                                 |

## API examples

```bash
# Insert
curl -X POST http://localhost:8080/api/movies \
     -H "Content-Type: application/json" \
     -d '{"title":"Inception","genre":"Sci-Fi","ticketPrice":250.00}'
# -> 201 {"message":"Movie added successfully with ID 1.","movie":{"movieId":1,...}}

# Update
curl -X PUT http://localhost:8080/api/movies/1 \
     -H "Content-Type: application/json" \
     -d '{"title":"Inception (IMAX)","genre":"Sci-Fi","ticketPrice":399.99}'
# -> 200 {"message":"Movie with ID 1 updated successfully.", ...}

# Delete
curl -X DELETE http://localhost:8080/api/movies/1
# -> 200 {"message":"Movie with ID 1 deleted successfully."}
```

Errors return JSON such as:

```json
{"status":400,"message":"Please correct the highlighted fields.","errors":{"ticketPrice":"Ticket price must be greater than 0."}}
```

Status codes: `201` created, `200` OK, `400` invalid input, `404` movie ID not found, `415` wrong content type.

## Troubleshooting

- **`release version 17 not supported`**: your JDK is older than 17. Install JDK 17+ and point `JAVA_HOME` to it.
- **`Port 8080 already in use`**: start with another port (see above).
- **`Database may be already in use`**: another CineBook instance is running against the same `./data` file. Stop it first.
- **`./mvnw: Permission denied`** (Linux/macOS): run `chmod +x mvnw`.
